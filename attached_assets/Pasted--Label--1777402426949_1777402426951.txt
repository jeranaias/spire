  # Edge cases / how to handle blockers

  - If a tool requires a backend route that doesn't exist, ADD a thin route in the appropriate `routes/*.py` file. Don't reimplement existing logic.
  - If a sweep touches `backend/auth.py` session middleware, STOP and flag — that file is locked.
  - If a praise issue's body has an actionable suggestion buried in it, treat as enhancement and triage accordingly — don't auto-close.
  - If a "deferred" enhancement turns out to be cheap (<2h) once you start, just do it.
  - If you discover a NEW bug while fixing an old one, file a new issue (use `gh issue create` with `type:bug` label) rather than expanding scope.
  - If you run out of context mid-session, your last act is to update `SPIRO_TOOLS_AND_BACKLOG.md` with exact next steps and stop. User resumes in a fresh chat.
